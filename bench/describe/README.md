# DESCRIBE bench

Does an entity's browse surface facts about the entity? Thirty-six entities
across six kinds, with the truth derived rather than typed.

- `entities.tsv` — query, Wikidata id, kind. These are held out of every
  relevance background: the hand panel by a test in `relevance.rs`, the
  corpus by `scripts/build-entity-corpus.py`.
- `targets.json` — generated by `bench.py --refresh`: labels in fifteen
  languages of the values of defining Wikidata properties (instance of,
  country, citizenship, capital of, occupation, field, genre, industry,
  continent, language, demonym, parent taxon, headquarters, author,
  director, creator). Not: member of, owner of, part of, notable work —
  true, but hundreds of labels per entity.
- `bench.py` — runs DESCRIBE per entity against larql (`--larql URL`) or the
  Divinci API (`--divinci URL --workspace ID`, bearer from `$TOKEN`), matches
  edges to targets, prints per-entity ranks and aggregate metrics, writes a
  JSON with `--out`, diffs against a stored run with `--baseline`.
- `baselines/` — stored runs. Name them by date, endpoint and params.

## Matching

An edge is on-target when any word of any target (≥4 letters, a stop-list
removed, and any word that is a target for a quarter or more of the bench
removed) shares a five-letter stem with the edge's label or one of its
neighbour tokens. Conservative by design: "French" matches "France" and
"physicist" matches "physics", "science" does not match "physics".

The stem matcher does hit by accident ("Interview" ← "internationales").
Every run reports `chance_hit@10`: each entity's edges scored against every
*other* entity's targets. Read `hit@10` against it — 0.58 vs 0.09 on the
first run — and never trust a change smaller than the chance rate moves.

## Metrics

`hit@k`: share of entities whose first on-target edge is in the top k.
`mrr`: mean of 1/first-rank. `hits_top10_mean`: on-target edges in the top
ten, averaged. `generic_share_top10`, `func_share_top10`: heuristic lists of
always-on and language-function labels from the 2026-09-04 measurements,
reported so a change that trades one for the other is visible. Per-kind
`hit@10` and `mrr`, because the kinds behave very differently.

## First run (2026-09-04, production, default params)

hit@1 0.25, hit@5 0.47, hit@10 0.58, mrr 0.35, chance 0.09. By kind:
company 1.0, person 0.7, city 0.67, country 0.67, other 0.2, work 0.0.
Lisbon, Havana, Peru, Norway, Beethoven, Obama, every work and most of
"other" surface nothing about themselves: the lexical query has nothing to
find. That is the ceiling the ranking work has reached, and the reason the
next step is retrieval, not ranking.

```
bench/describe/bench.py --refresh
TOKEN=… bench/describe/bench.py --divinci https://api.example --workspace WS \
    --out bench/describe/baselines/$(date +%F)-prod-entities.json
TOKEN=… bench/describe/bench.py --divinci … --param background=corpus \
    --baseline bench/describe/baselines/2026-09-04-prod-entities.json
```
